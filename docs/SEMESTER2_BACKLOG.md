# 2026학년도 2학기 백로그

## 운영 원칙

- 모든 구현은 WBS ID와 GitHub 이슈의 완료 기준에 연결합니다.
- 기능 브랜치에서 구현하고 기존 구조 검사 테스트를 merge gate로 유지합니다.
- 일정이 지연되면 구조 검사 정확성, 오류 진단, 자동 테스트, 재현 가능한 데모 순으로 보존합니다.
- 실행과 시각화는 구조 검사 코어의 신뢰성을 훼손하지 않는 범위에서 확장합니다.
- 매주 `docs/status/`에 완료·지연·위험·다음 계획을 기록합니다.

## 현재 기술 부채

1. 모듈 본문, 변수, 함수와 제어 흐름이 없습니다.
2. 실제 함수 호출과 `depends` 선언의 일치 여부를 검사하지 않습니다.
3. 긴 계층 체인에서 검사 시간이 빠르게 증가합니다.
4. 의존 그래프 시각화와 실제 corpus 기반 정량 평가가 없습니다.
5. 주간 status 기록을 S7부터 지속해야 합니다.

성능 기술 부채의 재현 조건과 최초 측정값은 [성능 기준선](PERFORMANCE_BASELINE.md)에 기록합니다.
